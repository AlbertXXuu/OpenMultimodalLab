# Ailumetra：在 8 GB 消费级 GPU 上，把多模态模型对比变成可复核证据

选择本地视觉语言模型时，我们经常看到一张成功截图、一个平均分，或者一条
缺少环境信息的结论。但真正准备在自己的电脑上运行模型时，更重要的问题是：
**同一组任务、同一台硬件、同一套推理协议下，哪个模型更合适，失败和性能
代价是什么，别人能否复核？**

为此，我开发了 Ailumetra 背后的开源评测引擎 OpenMultimodalLab。它不是通用
排行榜，而是一套本地优先、证据优先的多模态评测工作流。

## 它解决什么问题

项目把一次评测拆成五个可检查的部分：

1. 用带版本号的 JSONL 描述图片、文档截图和短视频任务；
2. 用统一 Adapter 驱动真实本地多模态模型；
3. 保存每条输出、失败、重试、耗时和显存数据；
4. 用任务指定的确定性规则评分；
5. 从原始记录生成 Markdown、CSV 和 SVG 报告，不重新运行模型。

原始 JSONL 才是事实来源，图表只是可以重新生成的派生物。运行清单还绑定了
数据集、媒体、模型 revision、Git 提交和环境信息的哈希，以减少“同名实验、
不同输入”的问题。

## v1.0 的实际证据

首个公开版本在 NVIDIA RTX 4060 Laptop GPU（8,188 MiB）上，对固定 revision
的 Qwen3-VL-2B 和 SmolVLM2-500M-Video-Instruct 运行了同一套 102 条人工检查
任务：

- 图片、文档截图、短视频和视觉鲁棒性任务；
- 每个模型 1 次 warm-up、3 次完整正式重复；
- 共 612 次正式测量，运行失败为 0；
- 同时记录质量、TTFT、任务延迟、吞吐和峰值已分配显存。

Qwen 的平均任务得分为 0.784，中位 TTFT 为 120.5 ms；SmolVLM2 的平均任务
得分为 0.690，中位 TTFT 为 260.0 ms。SmolVLM2 的峰值已分配显存约低 70%，
并在部分 OCR 和事件顺序任务中领先。这说明结果应该被理解为具体任务和硬件
上的取舍，而不是“某个模型永远更好”。

## 项目刻意保留的限制

当前语料全部是许可证清晰、可重新生成的受控合成媒体，只比较了两个小模型，
正式结果也只来自一台 GPU。因此这些数字不能直接推广到真实照片、复杂扫描件、
其他显卡或 7B 以上模型。公开这些限制，是为了让后续扩展回答明确的新问题，
而不是不断增加看起来更大的数字。

## 如何体验

仓库：<https://github.com/AlbertXXuu/OpenMultimodalLab>

第一次体验可以先运行零模型依赖的 smoke 流程；拥有 8 GB NVIDIA GPU 的用户
可以按 Qwen3-VL 或 SmolVLM2 教程运行真实后端。项目还提供本地 Ailumetra
Studio，用于上传单张图片、文档截图或短视频并查看模型回答和运行指标。
