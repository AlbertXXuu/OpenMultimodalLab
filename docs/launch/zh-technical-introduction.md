# Ailumetra：在 8 GB 消费级 GPU 上，把多模态模型对比变成可复核证据

选择本地视觉语言模型时，一张成功截图或一个平均分并不够。真正需要回答的是：
**在相同任务、硬件和推理协议下，模型的质量、速度、显存占用和失败情况分别如何，结果能否被他人复核？**

为此，我开发了 Ailumetra 背后的开源评测引擎 OpenMultimodalLab。它不是通用排行榜，而是一套面向本地硬件的多模态评测工作流。

## 它做什么

项目使用版本化 JSONL 描述图片、文档截图和短视频任务，通过统一 Adapter 运行真实开源模型，并逐条保存输出、失败、重试、耗时和显存数据。原始 JSONL 是事实来源，Markdown、CSV 和 SVG 报告均可从原始记录重新生成。

运行清单还记录数据集、媒体、模型 revision、Git 提交和环境哈希，减少“实验名称相同，实际输入不同”的复现问题。

## v1.0 的实测结果

首个公开版本在 NVIDIA RTX 4060 Laptop GPU（8,188 MiB）上，对固定 revision 的 Qwen3-VL-2B 和 SmolVLM2-500M-Video-Instruct 运行同一套 102 条人工检查任务：

- 覆盖图片、文档截图、短视频和视觉鲁棒性任务；
- 每个模型先 warm-up，再完成 3 次正式重复；
- 共 612 次正式测量，运行失败为 0；
- 同时记录质量、TTFT、任务延迟、吞吐和峰值显存。

Qwen 的平均任务得分为 0.784，中位 TTFT 为 120.5 ms；SmolVLM2 的平均得分为 0.690，中位 TTFT 为 260.0 ms，但峰值显存约低 70%，并在部分 OCR 和事件顺序任务中领先。

结论不是“哪个模型永远更好”，而是：**Qwen 在这套任务上质量和响应速度更优，SmolVLM2 则提供了明显更低的显存成本。**

## 适用边界

当前语料是许可证清晰、可重新生成的受控合成媒体，只比较了两个小模型，正式结果也来自同一台 GPU。因此这些数字不能直接推广到真实照片、复杂扫描件、其他显卡或 7B 以上模型。项目会明确保留这些限制，而不是把局部结果包装成普遍结论。
