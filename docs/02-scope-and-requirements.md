# 范围与需求

## 1. MVP 用户故事

### 模型使用者

作为开发者，我希望用一个任务文件运行不同模型，并得到统一结果，从而判断哪个模型更适合我的输入和硬件。

### 实验复现者

作为复现者，我希望知道每条结果使用了什么模型、配置、环境和数据，从而可以重新运行并验证结论。

### 开源贡献者

作为贡献者，我希望只实现清晰的 Adapter 接口就能增加模型，而不需要修改任务加载、评分和报告代码。

## 2. MoSCoW 范围

### Must：v1.0 必须有

- JSONL 任务集及 schema 校验。
- 可替换模型 Adapter。
- 图片、文档、短视频输入。
- 原始运行记录和失败记录。
- 基础准确率、延迟、吞吐、显存指标。
- 两个真实开源模型后端。
- CLI、测试、CI、安装和复现文档。

### Should：应当有

- 模型与任务过滤。
- 配置文件和运行清单。
- HTML 或 Markdown 对比报告。
- 断点续跑。
- 结果缓存和重复实验支持。
- 简单 Web Demo。

### Could：时间允许再做

- API 模型后端。
- 多模态 Agent 工具调用。
- 自定义排行榜。
- Hugging Face Space 演示。
- 量化格式自动建议。
- 中英文自动报告。

### Won't：v1.0 不做

- 训练基础模型。
- 多租户账户和支付。
- 移动 App。
- 分布式训练平台。
- 依赖大量人工主观评分的综合榜单。

## 3. 功能需求

### FR-01 任务加载

系统读取 UTF-8 JSONL。每条任务至少包含唯一 `id`、`prompt`，可以包含媒体路径、期望关键词、分类和元数据。

### FR-02 输入校验

运行前检查必填字段、重复 ID、媒体是否存在以及字段类型。错误必须指出行号和原因。

### FR-03 模型适配

所有后端实现统一生成接口，返回文本、模型信息和可选的 token/设备指标。测试后端不得混入正式榜单。

### FR-04 运行记录

每条样本单独写入记录。即使运行中断，已经完成的样本仍能保留。

### FR-05 评价

支持旧版确定性关键词评价，以及任务显式选择的规范化精确匹配和属性组评价；后续针对 OCR、结构化抽取和图表增加专用评价器。

### FR-06 报告

报告必须从原始记录生成，至少包含任务数、成功率、平均得分、延迟分布和失败类型。

## 4. 非功能需求

- **可复现**：保存模型 revision、配置和环境信息。
- **可扩展**：增加 Adapter 不修改核心 Runner。
- **可测试**：核心流程可以用确定性后端离线测试。
- **可诊断**：错误包含任务 ID、后端和根因。
- **安全**：默认不上传用户媒体，不记录密钥。
- **可维护**：公共函数有类型标注，数据格式有版本。

## 5. 第一阶段任务格式

```json
{
  "schema_version": "1.1",
  "id": "shapes-001",
  "prompt": "Describe the shapes and colors in the image.",
  "media": ["examples/assets/shapes.svg"],
  "expected_keywords": ["red circle", "blue square"],
  "scoring": {
    "type": "attribute_groups",
    "groups": [["red", "circle"], ["blue", "square"]],
    "ordered": false
  },
  "metadata": {
    "dataset_version": "synthetic-v1.1",
    "category": "image-description",
    "language": "en"
  }
}
```

`schema_version: "1.0"` 继续按旧关键词覆盖率读取；`1.1` 必须声明评分器。后续 schema 会增加媒体类型、结构化参考答案和许可证来源，但必须保持版本迁移说明。

## 6. 隐私与许可证要求

- 默认只读取本地媒体。
- 正式数据必须记录来源与许可证。
- 不使用来源不明的网络图片作为公开任务。
- 不提交模型权重。
- 用户提供的私有媒体不得默认进入日志或样例。
