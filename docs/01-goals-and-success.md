# 目标与验收标准

## 1. 12 周主目标

在 12 周内发布 OpenMultimodalLab `v1.0`：它能够在统一、版本化的任务集上运行至少 2 个真实开源视觉语言模型，处理图片、文档和短视频输入，记录质量、延迟、吞吐、峰值显存与失败类型，并通过一条命令重跑实验、通过另一条命令从原始记录重建报告。

完成必须同时满足：

- 功能验收通过；
- 自动测试和 CI 通过；
- 至少一次完整公开实验能够由文档复现；
- README、架构、评测协议和贡献指南齐全；
- 所有公开数字能追溯到原始结果。

## 2. 可量化关键结果

### KR1：可运行性

- Python 包可以在全新虚拟环境中安装。
- Windows 和 Linux 至少各有一套明确安装说明。
- `doctor` 命令能检查 Python、设备和关键依赖。
- `run` 与 `report` 命令分别完成运行和报告重建。

### KR2：模型与输入

- 1 个确定性测试后端。
- 至少 2 个真实开源模型后端。
- 支持图片、文档和短视频三类输入。
- 模型后端可替换，任务集和评价代码不需要跟着修改。

### KR3：任务与指标

- 至少 100 条人工检查、版本化的评测任务。
- 至少覆盖视觉描述、OCR/文档、图表推理、空间关系四类能力。
- 每个正式配置至少重复 3 次。
- 每条记录包含状态、输出、评分、耗时、配置和失败类型。

### KR4：工程质量

- 核心模块存在自动测试。
- 所有测试在 CI 中通过。
- 对无效 JSONL、缺失媒体、超时和适配器异常给出明确错误。
- 不把密钥、模型文件、原始大数据或运行产物提交进 Git。

### KR5：公开质量

- 英文主 README 和中文说明。
- 第一屏包含定位、效果图或结果示例、快速开始。
- 至少 1 个可复制的完整实验教程。
- 有 Roadmap、Contribution Guide、Issue 模板和许可证。
- 发布至少 3 个带 Release Notes 的版本：`v0.1`、`v0.5`、`v1.0`。

## 3. 近期目标：第一周

第一周的目标不是接入大模型，而是完成可靠的最小评测闭环。

验收命令：

```powershell
python -m pip install -e .
oml doctor
oml run --dataset examples/tasks/smoke.jsonl --output runs/smoke.jsonl
oml report --input runs/smoke.jsonl
python -m unittest discover -s tests -v
```

通过标准：

- 五条命令均以退出码 0 完成；
- 结果文件包含每个任务的响应、延迟、得分和状态；
- 报告中的任务数和成功数正确；
- 自动测试全部通过；
- 文档明确说明 `mock` 结果不能用于模型能力结论。

## 4. 目标边界

本目标包括：

- 评测数据结构；
- 模型适配层；
- 运行、记录、评分、报告；
- 两个真实开源多模态模型；
- 基础工程化和开源文档。

本目标不包括：

- 从头训练大模型；
- 商用 SLA；
- 大规模分布式训练；
- 完整的 SaaS 用户系统；
- 用不透明的主观印象替代评测协议。

## 5. 需要暂停并重新决策的情况

出现以下情况时，不继续盲目增加功能：

- 计划中的模型许可证不允许目标用法；
- 本地硬件无法运行任何候选模型；
- 数据集包含无法确认授权的媒体；
- 单周新增需求导致核心路线延误两周以上；
- 指标无法公平比较不同后端；
- 真实运行成本超出个人可承受范围。

此时应记录事实、替代方案和影响，再调整目标，不伪造或隐藏结果。

## 6. Star 与求职目标

Star 是外部结果，不能作为唯一完成条件。项目用以下可控指标代替：

- 至少 5 位非作者用户成功按文档运行；
- 至少收到 3 条有内容的外部 Issue、讨论或 PR；
- 快速开始的首次成功时间目标不超过 10 分钟，不含模型下载；
- 面试演示可以在 5 分钟内说明问题、架构、实验和结果。

这些数字在没有真实用户前保持为目标，不能写成已经完成。
