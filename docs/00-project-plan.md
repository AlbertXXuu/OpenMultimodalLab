# 项目规划书

## 1. 项目名称

工作名称：**OpenMultimodalLab**

一句话定位：

> 一个本地优先、可复现、可扩展的多模态模型评测与实验平台，让开发者能用统一任务和指标比较图片、文档、视频模型。

名称是工作名称。在第一次公开发布前检查 GitHub、PyPI 和域名重名情况，再决定是否更名。

## 2. 为什么做这个项目

多模态模型更新很快，但普通开发者经常遇到以下问题：

- 不同项目的输入格式、启动方式和硬件要求不一致。
- Demo 看起来很好，却没有统一任务和公平指标。
- 准确率、速度、显存和成本分散在不同报告里。
- 失败样本经常被隐藏，无法判断模型是否真正适合业务。
- 很多复现项目只有 Notebook，缺少测试、版本、CLI 和可重建报告。

本项目不训练基础模型，而是把模型的运行、测量、评价、对比和失败分析做成可靠的开源工具。

## 3. 目标用户

第一优先级：

- 想学习多模态 AI、计算机视觉和 AI 工程的学生。
- 只有个人电脑或消费级显卡的开发者。
- 需要选择开源视觉语言模型的个人项目或小团队。

第二优先级：

- 想贡献模型适配器、数据集或指标的开源开发者。
- 需要稳定实验入口的研究复现者。

## 4. 核心价值

| 用户问题 | 项目提供的价值 |
|---|---|
| 模型很难安装和切换 | 统一的 Adapter 接口和清晰的环境说明 |
| 不知道哪个模型更好 | 同一任务集上的准确率、速度、显存对比 |
| 结果无法复现 | 固定配置、版本、随机种子和原始 JSONL 记录 |
| Demo 只展示成功案例 | 保存失败类型、超时、OOM 和错误输出 |
| 想加入项目但不知从哪开始 | 小型贡献任务、模板和可测试的模块边界 |

## 5. 项目交付物

12 周内交付：

1. 一个公开 GitHub 仓库。
2. 可安装的 Python 包和命令行工具。
3. 至少 2 个真实开源模型适配器。
4. 图片、文档、短视频三类评测入口。
5. 至少 100 条经过检查的版本化任务。
6. 原始运行记录、汇总报告和失败分析。
7. 自动测试、CI、贡献指南和中英文项目说明。
8. 一个可以在简历和面试中完整讲解的架构与实验故事。

## 6. 实施原则

### 6.1 单一主线

前 12 周只做“多模态模型评测与实验平台”。3D、具身智能、AI Agent 和推理优化只能作为后续模块，不能打断第一版主线。

### 6.2 小步垂直交付

每个阶段都必须形成完整链路，而不是只建空目录。例如，第一个版本用 `mock` 后端跑通任务加载、推理、评分、记录和报告；第二个版本再用真实模型替换后端。

### 6.3 证据优先

每个公开结论必须附带：

- 模型与 revision；
- 运行环境和硬件；
- 输入数据版本；
- 推理参数；
- 重复次数；
- 原始结果位置；
- 已知限制。

### 6.4 控制资源

优先支持 8GB～12GB 显存或 CPU 可运行的小模型。大模型可以提供远程后端，但不能成为完成核心功能的前置条件。

## 7. 时间投入

推荐每周 10～12 小时：

- 5～6 小时：实现和测试；
- 2～3 小时：实验与结果检查；
- 2 小时：文档、Demo 和发布；
- 1 小时：阅读论文、Issue 和下周规划。

如果每周不足 8 小时，优先减少模型数量和 UI，不降低测试与复现标准。

## 8. 阶段出口

| 阶段 | 出口条件 |
|---|---|
| v0.1 基础闭环 | `mock` 后端可端到端运行，测试通过，结果可汇总 |
| v0.2 第一真实模型 | 至少一个开源 VLM 完成 10 条图片任务 |
| v0.3 公平评测 | 两个模型使用同一任务、参数规则和报告格式 |
| v0.5 多输入 | 图片和文档稳定，短视频实验入口可运行 |
| v0.8 可公开试用 | 安装、错误提示、文档、CI 和样例达到公开标准 |
| v1.0 | 满足目标文档中的全部必选验收项 |

## 9. 暂不承诺

- 不承诺 GitHub Star 数量。
- 不承诺达到任何论文的 SOTA。
- 不训练通用基础模型。
- 不在 v1.0 前支持所有模型框架。
- 不为了周更频率发布没有使用价值的提交。

## 10. 完成后的面试叙事

面试时应能清楚回答：

1. 为什么需要统一评测，而不是直接看模型榜单？
2. Adapter、Runner、Evaluator 和 Reporter 为什么要分层？
3. 如何保证两个模型的比较公平？
4. 如何测量延迟、吞吐和显存，边界在哪里？
5. OOM、超时和格式错误为什么不能被丢弃？
6. 你遇到过什么真实问题，如何用测试和数据定位？
7. 项目被其他人使用或贡献后，你如何维护兼容性？
